# v0.3 — UX polish, zero-setup install, full automation

**Status: Stable**
**Released: 2026-05-17**

---

## What this release solves

v0.2 worked, for someone willing to read a README. v0.3 makes it work for everyone else.

Three things were broken:

1. Fresh clone didn't work. Hardcoded paths, missing imports, wrong build command, and no vLLM on a clean machine meant a new contributor would spend an hour debugging before seeing the app.

2. Chat was functional but not pleasant. Markdown was unstyled, actions (copy/edit/regenerate) didn't exist, conversations had no right-click menu, and the error toast had no dismiss button.

3. The setup experience was invisible. The installer existed but wasn't triggered, the update flow depended on a banner that could be missed, and the migration cancel didn't work mid-copy.

## Fresh install automation

### The installer runs first, every time

On a clean machine:

1. `./start.sh` — detects OS, installs Rust + Bun if absent, creates backend venv, installs Python deps
2. Tauri launches. Frontend checks `/api/installer/status`
3. If `install_complete` is not set, InstallerApp opens instead of the main app
4. InstallerApp streams the full installation via SSE: llama-cpp-python compilation (CUDA/ROCm/Metal/CPU) + vLLM 0.21.0 install if NVIDIA detected
5. On completion, `install_complete=true` is written to DB and the main app opens on next `window.location.reload()`

The main app never opens until the engine is ready. No more "failed to import llama_cpp" on first launch.

### vLLM installed by default on NVIDIA

Previously: fresh clone → try to load AWQ model → "vLLM not available" → go to Settings → Engines → install → wait 20 min → try again.

Now: the installer detects NVIDIA, creates `~/.local/share/echohub/vllm-envs/0.21.0/`, and installs vLLM automatically. The user loads their AWQ model on first use.

### No more hardcoded paths

Every hardcoded `/mnt/projects/echohub` in the Python backend has been replaced with `Path(__file__).resolve().parents[N]`. The app works from any clone location, any user, any machine.

The `locate_project_root` function in Rust was also fixed: release builds used `resource_dir()` (wrong), now uses `current_exe().ancestors().nth(5)` consistently across debug and release.

### start.sh now launches cargo tauri dev

`cargo tauri build` requires `linuxdeploy` for AppImage bundling, which isn't installed by default. On a fresh machine, the build would fail with "failed to run linuxdeploy". `./start.sh` now runs `cargo tauri dev`, which compiles the Rust shell and starts the Vite dev server with hot reload.

For a release build: `cd frontend && cargo tauri build --no-bundle`.

### Compilation feedback during install

llama-cpp-python CUDA compilation takes 3–10 minutes. pip's "Building wheel for llama-cpp-python: still running..." repeats every 5 seconds for the entire duration.

The installer now collapses those repeated lines into a single timed counter: `Compiling… 4m22s elapsed (still working, this is normal)`. The user knows the install isn't frozen.

## Chat UX

### Message actions footer

Every message has a persistent action bar below it.

Assistant messages: Copy (copies the full message text, shows a checkmark for 1.5 seconds) and Regenerate (drops the last assistant message and re-runs generation from the same history).

User messages: Copy, Edit (opens an inline textarea with the message content — Enter submits, Escape cancels — the edited message replaces the original and triggers a new generation), and Regenerate (re-sends the conversation up to and including this message).

Stats (tokens, tok/s, time, model name) are shown in the same footer row.

Implementation note: `sendFromHistory(history)` in `useChat.ts` sends an existing message history directly to the inference endpoint without prepending a new user message. This is the correct primitive for both regenerate and edit. Stats are written directly into the in-memory message state at the end of each stream, so you don't need a reload to see them.

### Markdown rendering

Replaced the generic `prose prose-invert` Tailwind class with a fully custom component:

- Syntax highlighting via `highlight.js` with the `atom-one-dark` theme: proper colors for Python, TypeScript, Bash, JSON, etc.
- Language badge on code blocks, extracted from `language-*` class and cleaned of `hljs` prefix artifacts
- Code blocks with `#282c34` background matching atom-one-dark, subtle border, and a header with the language name
- h1–h4 headings with a clear size hierarchy
- Bullet `●` replacing browser defaults, with proper spacing
- Bordered tables with a distinct header
- Inline code with tinted background, accent color, no border clutter
- Text size `0.92rem`, line-height `1.7`

### Error toast with dismiss

The load failure toast now has a close `×` button and auto-dismisses after 60 seconds. Previously it was permanent and covered content until page reload.

## Conversation sidebar

### Right-click context menu

Right-clicking a conversation in the sidebar opens a menu: Rename (opens an inline input in the sidebar, Enter or blur confirms, Escape cancels), Archive/Unarchive, and Delete (red, separated by a divider). The same actions are available as hover icons on each row.

### Global context menu system

The native browser right-click menu is blocked everywhere in the app. Zones with registered actions (conversation items) show the custom menu. Zones with no actions show "No actions available". The menu auto-adjusts position to stay within the viewport.

Implementation: `ContextMenuProvider` wraps the app root and intercepts all `contextmenu` events via `window.addEventListener`. `useContextMenu.ts` is a separate file from `ContextMenu.tsx` — required for Vite Fast Refresh compatibility (components and hooks cannot coexist in the same file).

## Settings improvements

### About tab: update now inline

Previously: "2 updates available — check the notification bar." If you'd dismissed the banner or it hadn't appeared yet, you had no way to apply the update from Settings.

Now the About tab shows "Update now" directly when updates are detected, with inline logs and a "Restart now" button after success. The UpdateBanner is still there for proactive notification, but it's no longer the only path.

### Engines tab

The built-in vLLM environment gets a default badge; the delete button is disabled with the tooltip "Cannot delete — default installation". `LEGACY_VENV` path changed from hardcoded to `Path(__file__).resolve().parents[3] / ".venv-vllm"`, so it works on any clone. `_is_operational()` results are cached for 120 seconds (vLLM import takes 30–60 seconds cold; previously every refresh would block). The cache invalidates immediately after a successful install. A refresh button in the section header lets you force a re-check manually.

### Migration cancel & rollback

Once a file migration started, you had to wait for it to finish. On large model directories (50+ GB), that's a long wait if you picked the wrong destination.

Now a "Cancel & rollback" button is visible during the copy. On click, a flag is checked between every file copy, files already copied to the destination are deleted, the config is restored to the original path, and the migration state is cleared. The rollback is file-granular — it deletes exactly what was copied, nothing more.

## Technical notes for contributors

### Vite Fast Refresh rules

Vite's Fast Refresh requires that each file exports only one type of thing. Mixing a React component with a hook or a plain function will cause "Could not Fast Refresh" and a full reload. Rules in this codebase:

- Components go in `.tsx` files, one exported component per file
- Hooks go in separate `.ts` files (`useContextMenu.ts`, not inside `ContextMenu.tsx`)
- `createRoot` goes at module level, never inside an async function

### Backend path resolution

All Python service files resolve paths relative to their own location using `Path(__file__).resolve().parents[N]`. From `backend/services/`:
- `parents[0]` = `services/`
- `parents[1]` = `backend/`
- `parents[2]` = `echohub/` (project root)

Never use absolute paths. Never use `os.getcwd()`.

### installer_complete flag

The `install_complete` flag lives in the `app_state` table in `~/.local/share/echohub/echohub.db`.

To reset and replay the installer:
```bash
sqlite3 ~/.local/share/echohub/echohub.db "UPDATE app_state SET value='false' WHERE key='install_complete';"
```

## Known limitations in v0.3

- `.AppImage` packaging not validated: `cargo tauri build` requires `linuxdeploy`. Not tested since the build command was changed to `--no-bundle`. Will be addressed before public release.
- Old components not deleted: `frontend/src/components/*.tsx` (pre-refactor scaffold) still present in the repo. Not imported, harmless, but should be cleaned before public release.
- AMD ROCm / Apple Silicon still untested on real hardware. Code paths exist, behavior unverified.
- InstallerApp race condition: if the backend takes more than 30 seconds to start (slow machines), the frontend's retry loop times out and falls through to the main app.
