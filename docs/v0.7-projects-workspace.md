# v0.7 — Projects Workspace & Tool Calling

## What this is

v0.7 adds a structured workspace layer on top of the chat. The "Chat" and "Projects" switcher in the topbar routes between free conversation (unchanged) and a project-oriented workspace with mode-specific layouts, profiles, and tooling.

---

## Projects system

### Hub

Clicking "Projects" lands on a project hub — a grid of all projects with create, archive, delete, rename, and full-text search by name.

Each project has a **type**:
- **Dev** — code-oriented workspace, requires tool-calling capable model
- **Docs** — document writing and context injection
- **Research** — analysis, synthesis, source management

Filter tabs: All / Dev / Docs / Research / Archived. Context menu (right-click) for rename/archive/delete. Create form inline with type selector.

Projects are persisted in `localStorage` under `echohub:projects`.

### Workspace

Opening a project switches to the workspace layout:
- Left panel: type-specific (Project Files for Dev, Context Files for Docs, Sources for Research) — both collapsible with animated toggle button
- Center: full chat interface
- Right panel: profile sidebar, scoped to the project — also collapsible

The topbar shows `← project-name` to navigate back to the hub. The mode selector disappears — the type is fixed to the project.

### Project-scoped profiles

Each project gets its own `useProfiles` instance, keyed to `{ mode, projectId }`. Storage key: `echohub:profiles:{projectId}`. Opening a different project mounts a fresh component instance (`key={project.id}`) — no cross-contamination between projects or with the chat.

**Default profiles per type:**

| Type | Profiles |
|---|---|
| Dev | Dev (temp 0.2, thinking on, engineer prompt), Debug (temp 0.1, root-cause focused), Code Review (temp 0.3, senior reviewer) |
| Docs | Writer (temp 0.5, technical writer), Summarizer (temp 0.3, TL;DR + bullets), Translator (temp 0.4, preserve tone) |
| Research | Analyst (temp 0.4, evidence-based, thinking on), Brainstorm (temp 0.9, creative), Fact-check (temp 0.1, confidence rating) |

All profiles editable, saveable, deleteable (builtins protected unless user-modified).

## Tool calling detection

### Discover filter

New "Tools" filter in Discover alongside Vision and Thinking. When active, queries HuggingFace directly using the actual tag values used by tool-calling models: `tool-calling`, `function-calling`, `tool-use` — three separate passes, deduped.

When combined with a format filter (e.g. GGUF + Tools), runs cross-product passes: `[gguf, tool-calling]`, `[gguf, function-calling]`, `[gguf, tool-use]`.

### Detection logic (`_detect_capabilities`)

Expanded from 2 tags to:
- **HF tags**: `function-calling`, `tool-use`, `tools`, `tool_use`, `tool-calls`, `function_calling`, `agent`, `agentic`, `hermes`, `nexusflow`, `gorilla`
- **Model name patterns**: `hermes`, `gorilla`, `nexus`, `functionary`, `xlam`, `toolbench`, `toolllm`, `hammer`, `meetkai`
- **Local tokenizer scan**: reads `tokenizer_config.json` for downloaded models, checks `chat_template` for `tool`, `function_call`, or `<tool_call>` — ground truth for local models

### Tools badge

Yellow `tools` badge (`bg-yellow-500/15 text-yellow-400`) added to:
- ModelCard in Discover
- ModelPickerModal (Switch model)
- CapabilityBadges component

The badge also appears in the Dev panel left sidebar if the loaded model lacks tool calling: amber warning "Load a model with tool calling to use Dev mode".

## Layout changes

### Topbar restructure

The topbar was moved to span the full page width (above sidebars). Previously it was inside the center column — the right panel started at the top of the page, visually overlapping the topbar area.

Structure before: `[sidebar] [topbar + content]` (horizontal flex)
Structure after: `[topbar] / [sidebar + content + right-panel]` (vertical flex, topbar full-width)

### Collapsible panels

Both left and right panels have a collapse toggle — a `‹` arrow button anchored to the outer edge, vertically centered. Framer Motion width animation (200ms easeInOut). State managed locally in `ChatPage` (chat) and `ProjectsPanel` / `ProjectWorkspace` (projects).

---

## UX details

- Send button: replaced paper-plane icon with arrow-up (`↑`) — cleaner, universally recognized
- Dev mode warning banner: background-only, no border
- Mode selector (Dev/Docs/Research) hidden when inside a project workspace and when in the projects hub — it was redundant
- Archived projects: shown in dedicated tab, not mixed with active ones
- Projects hub: search input filters by name in real time, combined with tab filter
