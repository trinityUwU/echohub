# v0.2 — Multi-engine vLLM

**Status: In progress**

---

## The problem this solves

vLLM releases new versions every few weeks. Each version adds support for new model architectures, fixes quantization bugs, and improves performance. But you can't just upgrade — a newer vLLM might break models that worked fine on the previous version.

In v0.1, EchoHub ships with one vLLM version (0.21.0). If a model needs a different version, you're stuck.

v0.2 fixes this completely.

---

## What v0.2 ships

### Multiple vLLM versions, side by side

Each vLLM version lives in its own isolated Python environment:

```
~/.local/share/echohub/vllm-envs/
  0.21.0/    ← ships with the app
  0.8.5/     ← installed later for older model support
  0.22.0/    ← installed for newer architectures
```

They don't interfere. You can have three versions installed and each one handles the models it's compatible with.

### Automatic compatibility routing

When you load a model, EchoHub checks which vLLM version it needs and uses that one. You don't pick the version — the app does.

If no compatible version is installed, you see:

> "This model requires vLLM ≥ 0.22. Install it? (~6 GB, ~20 min)"

One click. The app downloads, installs, and verifies the new version in the background with live logs.

### Settings / Engines tab

Full visibility into what's installed:

- Version number
- Disk usage
- Operational status (tested, not just installed)
- Model architectures covered
- Whether it covers enough common models to be worth keeping

If you only have one version installed, delete is disabled — the app won't let you break itself.

### Coverage warning

If your installed vLLM versions collectively cover less than ~20% of commonly downloaded model architectures, the app tells you:

> "Your current vLLM installation covers limited model types. Installing additional versions would give you access to significantly more models."

Opt-in, informational. Not a nag.

## The installation problem

Installing vLLM with CUDA support is not simple. It involves:

1. Creating an isolated Python virtual environment
2. Installing the right torch version for your CUDA version
3. Installing vLLM (which may compile CUDA extensions)
4. Verifying the install actually works (import test, not just file presence)

On a clean system this takes 10–30 minutes. EchoHub makes this a background task with real-time log streaming so you see exactly what's happening and why it's taking time.

---

## What we're NOT doing

- We're not building a package manager
- We're not modifying system Python or system packages
- We're not requiring the user to know anything about Python environments

Everything lives in `~/.local/share/echohub/`. Uninstalling EchoHub removes everything cleanly.
