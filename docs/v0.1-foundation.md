# v0.1 — Foundation

**Status: Stable**  
**Released: 2026-05-16**

This document covers what EchoHub v0.1 shipped, the technical problems it solved, and why the solutions are non-trivial.

---

## What shipped in v0.1

- Native desktop app (Rust/Tauri v2) — no browser, no Electron overhead
- Model discovery: search Hugging Face directly from the app
- Two inference engines running side by side
- Real-time VRAM management with preview before load
- Streaming chat with conversation history (SQLite)
- Vision model support (attach images, Ctrl+V paste)
- Chat profiles with saved parameters (temperature, context, system prompt)
- Model compatibility detection before download
- Favorites system for models
- Full model detail panel with README, GGUF variants, VRAM per variant

## The hard parts

### Two inference engines, one interface

Running AI models locally is fragmented. GGUF models need llama.cpp. AWQ/GPTQ models need vLLM. They have completely different APIs, different startup sequences, and different failure modes.

EchoHub abstracts all of this. You click "Load". The app detects the model format, picks the right engine, starts it, and waits for it to be ready. From the chat interface, you never know which engine is running.

llama-cpp-python is compiled from source with CUDA support (on NVIDIA), ROCm (AMD), or Metal (Apple Silicon). The compilation flags are derived automatically from the hardware, including the Arch Linux + CUDA 13 + gcc-15 specific flags for RTX 3060.

vLLM runs as an isolated subprocess with its own Python environment. It exposes an OpenAI-compatible API on a local port. EchoHub manages the lifecycle: start, health polling, graceful shutdown, VRAM cleanup verification.

### VRAM management is genuinely hard

A 12 GB GPU doesn't give you 12 GB. The OS takes some. CUDA runtime takes some. The model weights take some. The KV cache grows with context length. CUDA graphs take ~1.2 GB. Get the math wrong and the process crashes, sometimes silently.

EchoHub shows a live preview before loading:
- System usage (measured, not estimated)
- Model weights (from disk file size, corrected for quantization)
- KV cache estimate (scales with context length and model parameters)
- CUDA overhead
- GPU utilization limit (the vLLM parameter that caps total allocation)

If the model doesn't fit, the Load button stays disabled. If it barely fits and fails anyway (within ~50 MB), the app retries automatically with a slightly lower utilization percentage.

### Model compatibility is a moving target

vLLM 0.21 supports ~200 model architectures. A model released last month might use an architecture not in that list, or use a quantization variant that triggers an alignment bug in the AWQ loader (e.g. multimodal AWQ models with custom `modules_to_not_convert`).

Before you download a model, EchoHub fetches its `config.json` from Hugging Face and checks:
- Is the architecture in the supported list?
- Is it a multimodal model with AWQ quantization? (Known issue in vLLM 0.21)
- What's the minimum vLLM version required?

If there's an issue, you see a warning with an explanation and a recommendation — before downloading gigabytes of data.

### The app is self-contained

The Python backend starts automatically when you open the app (Rust spawns it as a subprocess on a random free port). When you close the app, the backend and any running inference engine are killed cleanly.

Open the app, it works. Close the app, it stops.

## Technical stack

| Layer | Technology |
|---|---|
| Desktop shell | Rust · Tauri v2 |
| Frontend | React 18 · TypeScript · Tailwind · Vite · Bun |
| Backend | Python 3.11 · FastAPI · uvicorn |
| Inference (GGUF) | llama-cpp-python (CUDA/ROCm/Metal/CPU) |
| Inference (AWQ/GPTQ) | vLLM 0.21 — isolated venv |
| Database | SQLite WAL |
| Model storage | Configurable, default `/mnt/models/echohub/` |

## Known limitations in v0.1

- One vLLM version: if a model requires a newer vLLM, you can't use it (fixed in v0.2)
- vLLM on NVIDIA only: AMD ROCm support for vLLM not tested
- No packaging: requires building from source (fixed in v0.2)
- AWQ on multimodal vision models: some architectures hit an alignment bug in vLLM 0.21's AWQ loader; the compatibility check warns you before download
