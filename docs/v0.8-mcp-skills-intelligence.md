# v0.8 — MCP Skills Intelligence & Agent Polish

## What this is

v0.8 completes the Skills/MCP system started in v0.7 and makes the agentic loop
production-grade. The main additions: stdio transport for Python/Node MCP servers,
full automatic installation pipeline from GitHub, and a set of inference fixes that
prevent the agent from going off the rails.

---

## MCP stdio transport

### Problem
Most MCP servers on GitHub (Python FastMCP, official Anthropic MCP SDK) communicate
via **stdin/stdout**, not HTTP. The existing stack only supported HTTP health-check
based servers — Python MCP servers silently failed with "health check timeout".

### Architecture

New `backend/services/mcp_stdio_client.py`:
- `McpStdioClient` — long-lived subprocess, JSON-RPC 2.0 over stdin/stdout
- Pool singleton `_stdio_clients` per skill_id — one process per skill, reused across calls
- `asyncio.Lock` serializes calls — one in-flight at a time
- MCP initialize handshake on startup (`protocolVersion: 2024-11-05`)
- `notifications/initialized` notification sent after handshake
- Graceful shutdown: sends `shutdown` JSON-RPC request before SIGTERM
- Buffer limit: 8MB (default 64KB asyncio limit caused "chunk is longer than limit" on large search results)
- Timeout: 120s per call (network-heavy tools like paper-search-mcp take ~55s)

`mcp_client.py` now routes calls to HTTP or stdio based on `transport` column in DB.
`mcp_manager.py` — `_start_stdio()` handles lifecycle, skips HTTP health check for stdio,
patches `python`/`python3` in start_command to backend venv interpreter (or skill venv).

### Transport detection

`detect_mcp_server()` in `mcp_manager.py` — now detects transport in priority order:

1. **smithery.yaml** — command + transport + args extracted via regex (no yaml dep).
   `uvx`/`npx`/`node`/`python` without `--port` → stdio automatic.
2. **mcp.json / .mcp.json** — explicit transport field
3. **package.json** — scans TS/JS source for `StdioServerTransport` (definitive stdio
   marker for Node MCP). Monorepos (workspaces field) → return None (not installable at root).
4. **pyproject.toml** `[project.scripts]` → entry point → stdio
5. **setup.py** console_scripts → stdio
6. **Fallback** — no port in start_command → stdio, port found → http

### Auto-redetect at start

If `mcp_transport` is missing from a skill's registry.json (installed before v0.8),
`start_mcp_server` re-runs `detect_mcp_server()` and patches both the global registry
and the skill-local `registry.json` on disk.

## Automatic installation pipeline

End-to-end flow for any MCP server from GitHub:

1. **git clone** → `~/.local/share/echohub/skills/<id>/`
2. **Isolated venv** — `python3 -m venv .venv` + `pip install -e .` inside the skill dir.
   No cross-contamination between skills. Skill venv used at runtime if present,
   backend venv as fallback.
3. **detect_mcp_server()** — transport + start_command auto-detected
4. **registry.json** patched with `mcp_transport`, `mcp_start_command`, `mcp_port_hint`
5. **Start** — toggle ON, process launches, stdio client initializes, tools discovered

## Agent inference fixes

### Context budget awareness

Each tool result now includes a footer:
```
[Context: 45,000/131,072 tokens (34% used)]
```

At **75%**: strong warning injected into the tool result — model must stop researching
and synthesize. At **92%**: hard stop, all subsequent tool calls blocked, synthesis
forced.

### Synthesis on tool cap

When the agent hits its tool call limit (inline cap or MAX_ITERATIONS), instead of
`[Tool call limit reached. Resume in a new message.]`, a synthesis prompt is injected
as a user message:

> "You have reached the tool call limit. Stop all research immediately. Based on
> everything you have gathered so far, write a complete, well-structured final answer."

The model generates a complete response using all accumulated context.

### set_tool_limit awareness

The cap warning (fired at N-2 calls remaining) now explicitly tells the agent:
> "call set_tool_limit NOW with a higher value and a clear reason before continuing"

Previously it referenced "Settings > Dev mode" — the agent had no way to act on that.

### Timeout on MCP tool calls

`call_mcp_tool()` in inference was awaited without timeout. If a stdio process hung,
the LLM stream blocked indefinitely. Wrapped in `asyncio.wait_for(timeout=60.0)`.

## Message persistence fix

Skill-mode chat (MCP skills active) was not persisting messages to DB.
`skillChatHook` had no `onSaveMessage` callback — messages existed only in memory.
On conversation switch or app restart, the history was lost.

Fix: `skillChatHook` now receives `onSaveMessage` that calls `addMessage()` from the
API client, persisting the full accumulated content (including `<tool_call>` /
`<tool_result>` tags) after each assistant turn.

## Frontend improvements

### Context bar in projects
`usedTokens` was reset to 0 on `loadHistory` (conversation load). Now estimated
from history character count (`chars / 4`) — consistent with the rest of the hook.

### Message deduplication
`deduplicateMessages()` applied in `loadHistory` and `send()` — backend never
receives duplicate history entries. Keys on `role:content[:200]`, filters with a Set.

### Animated tool call blocks

`ToolCallBlock` and `ToolResultBlock` redesigned:
- Expanded by default during execution (spinner + "Executing…")
- Collapsed by default once done
- Click header to toggle open/close
- Framer Motion height animation (`AnimatePresence`)
- Design tokens: `bg-surface border-white/5`
- Word count in header, "done"/"running" badge

## Chat profiles

### 5 built-in profiles with real prompts

`useProfiles.ts` `CHAT_BUILTINS` rewritten from scratch:

| Profile | Temp | System prompt |
|---|---|---|
| **Default** | 0.6 | Direct, competent, no filler |
| **Precise** | 0.2 | Correctness over completeness, explicit confidence |
| **Creative** | 1.0 | Divergent, non-obvious angles, associative |
| **Balanced** | 0.7 | Analyst, tradeoffs, structured reasoning |
| **Coder** | 0.3 | Senior engineer, full-stack defaults, no pseudocode |

All profiles include **language mirroring** as rule #1:
> "Match the user's language exactly and immediately — no exceptions"

### localStorage upgrade path

`loadProfilesFromStorage` always uses fresh builtins for locked IDs — old localStorage
entries without prompts are replaced on next load, no migration needed.
