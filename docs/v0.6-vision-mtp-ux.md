# v0.6 — Vision, MTP, UX polish

Status: Stable
Released: 2026-05-19

This release adds MTP detection, vision model support for llama.cpp, capability badges throughout the UI, and several quality-of-life improvements to the chat interface.

---

## MTP (Multi-Token Prediction)

Models like Qwen3 and Gemma3 ship with extra prediction heads baked into their weights. llama.cpp uses these for speculative decoding — it generates multiple candidate tokens in parallel and verifies them in a single forward pass. The result is 1.5–2x faster generation with no quality change and no extra VRAM cost.

EchoHub detects MTP at two points. For local GGUFs, it parses the binary header and looks for tensors named `blk.N.nextn.*`. For models in Discover before download, it uses a name heuristic (Qwen3, Gemma3 families). The detection takes a few milliseconds and doesn't load the weights.

The binary scan result takes precedence over the heuristic for downloaded models — if the GGUF was exported without MTP tensors, the badge won't appear even if the model name suggests otherwise.

MTP activates automatically in llama.cpp when the tensors are present. Nothing to configure.

Fine-tune export preserves MTP: if you fine-tune a Qwen3 or Gemma3 model, the exported GGUF retains the MTP heads. The export log includes `MTP_DETECTED:true/false` and the done event carries `has_mtp`.

## Vision support for llama.cpp GGUFs

Vision models distributed as GGUF include two files: the main model weights and a multimodal projector (`mmproj-*.gguf`). When EchoHub detects a mmproj file in the model directory at load time, it selects the appropriate chat handler and passes it to llama-cpp-python.

Supported handlers: `Qwen25VLChatHandler`, `Llava15ChatHandler`, `Llava16ChatHandler`, `MiniCPMv26ChatHandler`, `Llama3VisionAlphaChatHandler`, `MoondreamChatHandler`. Handler selection is automatic from the model name.

If handler loading fails for any reason, the model loads in text-only mode without crashing.

The vision badge on downloaded GGUFs reflects ground truth: it only appears if a mmproj file is actually present in the model directory. This prevents false positives from HF tags like `image-text-to-text` that are sometimes applied to text-only fine-tunes.

For non-vision models, image content in messages is stripped server-side: the `image_url` parts are removed and only the text is forwarded to the model. This prevents the "message came through empty" failure that happened when llama.cpp received multimodal content it couldn't process.

## Capability badges

Badges now appear consistently across all model surfaces:

- Discover model cards: quant, MoE, MTP, thinking, vision, gated, loaded, downloaded
- Library cards: same set
- ModelPickerModal: badges inline under model name (not buried in muted subtext)
- ModelDetailPanel: MTP badge added alongside existing badges
- LoadModelModal: capability badges under model name before loading
- ChatTopBar: quantization and MTP badges next to the engine badge

The vision badge detection was also fixed to include `image-text-to-text` as a HF pipeline tag signal, in addition to the existing tag/name checks.

## Clipboard image paste on Wayland

Ctrl+V paste for images was broken on Linux/Wayland. The root cause: WebKitGTK doesn't expose image data through `clipboardData.items` on paste events, producing GDK UTF8_STRING conversion warnings. The fix uses a Tauri Rust command (`read_clipboard_image`) that calls `wl-paste` directly via subprocess — completely bypassing WebKit's clipboard handling.

On X11, `arboard` is used as fallback. The GDK warnings still appear (WebKit always tries UTF8 first) but are harmless and don't affect functionality.

The `visionEnabled` guard on paste was also removed — images can now be attached regardless of whether the current model supports vision. The model capability check happens at send time, not at paste time.

## Reload model from message footer

Each assistant message now stores the exact load configuration used to generate it: model_id, engine, n_ctx, n_gpu_layers, cpu_overflow, is_moe, gpu_memory_utilization, vllm_version, gguf_path.

When the currently loaded model differs from the one that generated a message — or no model is loaded — a reload button appears in the message footer. One click reloads that exact model with identical parameters.

For older messages that predate this feature, the button falls back to `stats.model_name` and `stats.engine` to construct a minimal config. Short model names from stats are resolved against the downloaded models list to find the full HF id.

Implementation: `load_config TEXT` column added to the messages table (auto-migrated on startup). `get_load_state()` now returns the full load config from the active engine. Config is captured at send time in `useChat.ts`, not after the stream completes.

Clicking any image thumbnail attached to a chat message opens it fullscreen with a dark backdrop and blur overlay. Framer Motion fade + scale animation. Click outside or the X button to close.

## vLLM fixes

Two vLLM bugs fixed this release:

The compatibility check was using a direct `import vllm` in the backend process, which always fails because vLLM lives in its own isolated venv. It now runs via subprocess using `get_default_python()` from `vllm_manager`, consistent with how the rest of the codebase handles vLLM calls. This gives access to 356 supported architectures instead of an error.

`max_tokens` overflow: when the total of prompt tokens + max_tokens exceeded `max_model_len`, vLLM returned a 400 error that surfaced as 0 tokens / 0 tok/s in the UI with no visible error message. Fixed by clipping `max_tokens` to `max_model_len - estimated_prompt_tokens` before sending the request.

## Known limitations

- Vision via llama.cpp requires a mmproj file in the model directory. Models distributed without it (most fine-tunes, text-only exports) can't use vision even if the base architecture supports it.
- MTP only works with llama.cpp. vLLM doesn't implement MTP-based speculative decoding.
- The Wayland clipboard fix requires `wl-clipboard` to be installed (`wl-paste` in PATH). It's standard on most Wayland desktops.
- The reload button resolves short model names by searching the downloaded models list. If the model was deleted from disk, the reload will fail at load time with a file-not-found error.
